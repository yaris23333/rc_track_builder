# RC Track Designer — v1 规格（桌面网页版）

> 状态：需求确认中
> 范围：桌面浏览器（≥1280×720），不做移动端
> 输出：PDF / DXF / 分享链接 / PNG 截图
> 日期：2026-11-05

---

## 1. 范围

### 做

- 桌面网页编辑器，鼠标 + 键盘；
- 正方形网格，格子边长 `0.3 / 0.5 / 1 m` 可选；
- 画布尺寸可通过「米」或「格数」双向设置；
- 瓦片放置、移动、旋转、翻转、删除、多选、撤销/重做；
- 平移/缩放/适配画布；
- 四种输出：PDF、DXF、分享链接、PNG 截图；
- 自动保存到 IndexedDB；
- 项目导入/导出 JSON；
- 深色/浅色主题。

### 不做（v1）

- 移动端/触屏适配；
- 多人实时协作；
- 3D 地形/物理引擎；
- 云端账号体系；
- 1:1 分页打印（v2）；
- 自动生成赛道。

## 2. 网格与画布模型（核心决策）

### 2.1 推荐模型：物理尺寸优先

**米是唯一事实来源，格子只是吸附/显示网格。**

```ts
interface Board {
  cellSize: 0.3 | 0.5 | 1;  // 米
  widthM: number;           // 画布实际宽度（米）
  heightM: number;          // 画布实际高度（米）
  // 派生：
  cols: number;             // ceil(widthM / cellSize)
  rows: number;             // ceil(heightM / cellSize)
}
```

理由：

- 你要导 DXF 给 CAD/Fusion/3ds Max，真实尺寸必须稳定；
- 改格子边长时，赛道不能跟着缩放或错位；
- 画布 30×20m 在 0.3m 网格下是 100×67 格，在 1m 网格下是 30×20 格，赛道几何不变；
- 格子只影响吸附精度和视觉密度。

### 2.2 另一种模型：格子优先（不推荐）

瓦片固定占 1 格，格子边长就是赛道比例尺：

- 改格子边长 = 整条赛道等比缩放；
- 实现更简单，但改网格会改变赛道真实尺寸；
- 导出 DXF 仍然正确，但「0.3m 网格」下的 90° 弯只有 0.3m 半径，物理上不合理。

**建议采用 2.1；如果你更想要「1 格 = 1 块瓦片」的简单模型，需要现在确认，因为数据模型不同。**

#### A/B 的一句话区别

- **A：瓦片的真实尺寸固定，格子占位随格子边长变化。**
- **B：瓦片的格子占位固定，真实尺寸随格子边长变化。**

#### 同一个场景对比

画布 30×20m，瓦片 3m×3m，把格子边长从 1m 切到 0.3m：

| | A. 物理优先 | B. 格子优先 |
|---|---|---|
| 画布 | 仍是 30×20m | 30×20 格 = 9×6m |
| 格数 | 30×20 → 100×67 | 30×20 不变 |
| 3m 瓦片 | 3×3 格 → 10×10 格，仍是 3m | 3×3 格不变，变成 0.9m |
| 赛道 | 不动 | 整体缩小 |
| 含义 | 提高网格精度 | 改变赛道比例 |

#### 类比

- **A 像在坐标纸上画房子**：换一张更细的坐标纸，房子不会变小，只是格子更多、量得更准。
- **B 像乐高底板**：格子是积木尺寸，换小格子，整座模型按比例缩小。

#### A 的代价

- 坐标用米，格索引是派生的，数学多一点；
- 改格子边长后，瓦片原点可能不在新网格上，需要「保持原位」或「对齐到新网格」；
- 画布米数不是格子整数倍时，v1 向上取整并显示实际尺寸；
- 换来的是 DXF/PDF/未来 1:1 打印的真实尺寸始终正确。

#### B 的优点

- 实现最简单；
- 瓦片永远贴合格子；
- 参考站就是 B；
- 如果只是做拼图/示意图，B 足够。

#### 结论

你要把 DXF 拿到 CAD/Fusion/3ds Max 里当工程草图，**选 A**。  
如果只是想快速复刻参考站、不在意真实尺寸，**选 B**。  
v1 默认按 A 设计。

### 2.3 瓦片尺寸

v1 瓦片库建议用 **3m × 3m 模块**：

- 3m 能被 0.3 / 0.5 / 1 整除；
- 在三种网格下分别占 10×10 / 6×6 / 3×3 格，永远不会出现半格；
- 3m 接近 1/10 RC 越野赛道的常见宽度/弯道尺度；
- 一个 30×20m 场地 = 10×6.67 个模块，适合做小型赛道方案。

瓦片定义：

```ts
interface TileDef {
  id: string;
  name: string;
  category: 'straight' | 'curve' | 'feature' | 'start' | 'accessory';
  sizeM: { w: number; h: number };   // 真实尺寸（米）
  origin: 'top-left';                // v1 统一
  geometry: GeometryLayer[];         // 本地坐标，米；SVG/DXF 共用
  ports?: Port[];                    // v1.1 再加
}
```

- 放置时原点吸附到网格；
- 瓦片尺寸不必是格子的整数倍（v1 的 3m 模块都是）；
- 旋转只支持 90° 的倍数，旋转后宽高互换；
- 翻转 H/V 只影响外观/几何镜像，不影响占位。

### 2.4 画布尺寸设置

画布设置面板：

| 字段 | 行为 |
|---|---|
| 格子边长 | 0.3 / 0.5 / 1 m 三选一 |
| 宽度 | 输入米，或切换到「格」输入整数 |
| 高度 | 同上 |
| 锁定比例 | 可选；改一边时另一边按比例跟随 |
| 预设 | 10×10、20×20、30×20、40×30、50×30 |
| 实际尺寸 | 实时显示 `30.0 × 20.1 m（100 × 67 格）` |

计算规则：

```ts
// 输入米 -> 格
cols = clamp(Math.ceil(widthM / cellSize), 1, MAX_CELLS); // MAX_CELLS = 500
widthM = cols * cellSize; // 回写实际值

// 输入格 -> 米
widthM = cols * cellSize;
```

- 米不是格子整数倍时，**向上取整**，并明确显示实际尺寸；
- 上限 500×500 格（0.3m 时 150×150m），防止误输入；
- 画布原点在左上角，DXF 导出时翻到左下角、Y 轴向上。

### 2.5 改变格子边长时

推荐行为：

1. 保持 `widthM / heightM` 不变；
2. 重新计算 `cols/rows`；
3. **赛道瓦片的米坐标不变**，因此赛道不缩放、不移动；
4. 瓦片原点如果不在新网格上，提示「对齐到新网格（最多移动 0.25m）」；
5. 整个操作可撤销。

这样用户可以在不破坏设计的情况下切换网格精度。

### 2.6 改变画布尺寸时

- 默认锚点：左上角；向右/下扩展；
- 扩大：保留现有瓦片，新增空白；
- 缩小：统计会被裁掉的瓦片，弹确认；确认后删除，可撤销；
- 画布尺寸变化不改变瓦片的米坐标；
- 提供「适配画布」视图按钮。

### 2.7 网格渲染性能

不要为每个格子渲染一个 DOM 节点。参考站 7×4 可以，100×67 也可以，但 500×500 会爆。

方案：

- 网格线用**一个 SVG `<path>`** 画（竖线 + 横线），不是 2.5 万个 `<rect>`；
- 每 5 或 10 格加粗/加深，形成主次网格；
- 标尺用 HTML/SVG 叠加；
- 瓦片用 SVG `<g>`，视口外裁剪；
- 平移/缩放只改一个 `<g>` 的 `transform`；
- 超过 3–5k 瓦片再考虑 Canvas/Konva，v1 不需要。

## 3. 数据模型

```ts
type Rot = 0 | 90 | 180 | 270;

interface PlacedTile {
  uid: string;
  defId: string;
  xM: number;          // 原点，米
  yM: number;
  rot: Rot;
  flipX: boolean;
  flipY: boolean;
  layer: number;       // v1 恒为 0
}

interface TrackDoc {
  schemaVersion: 1;
  name: string;
  board: {
    cellSize: 0.3 | 0.5 | 1;
    widthM: number;
    heightM: number;
  };
  tiles: PlacedTile[];
  meta: {
    author?: string;
    notes?: string;
    createdAt: string;
    updatedAt: string;
  };
  tileSetVersion: string;
}
```

- 稀疏存储，不存二维数组；
- 占位索引、连接图、长度、BOM 都从 `tiles` 派生；
- 撤销/重做用命令模式，不存整份文档快照；
- 自动保存：IndexedDB，防抖 500ms；
- 项目列表：最近项目、重命名、复制、删除；
- JSON 导入导出带 `schemaVersion`，预留迁移函数。

## 4. 四种输出

### 4.1 分享链接

目标：点开链接就能看，必要时可「复制到我的画布」继续编辑。

实现：

- 路由：`/#/s/<compressed>`（hash 不经过服务器，静态托管即可）；
- JSON → `fflate` deflate → base64url；
- 只包含必要字段：`board`、`tiles`、`name`、`tileSetVersion`；
- 查看模式：只读、适配画布、显示标题/比例尺；
- 编辑模式：点「复制到我的画布」加载为本地项目；
- 链接长度：
  - < 6KB：直接分享；
  - 6–20KB：提示可能被聊天软件截断；
  - > 20KB：禁用链接，建议导出 JSON 或使用短链服务。
- 安全：zod 校验、解压大小上限 2MB、不执行任何用户文本。

#### 纯静态 hash vs 短链后端

| 维度 | A. 纯静态 hash | B. 短链后端 |
|---|---|---|
| 数据在哪 | URL 里 | 服务器/KV |
| URL 形态 | `/#/s/eNq...` | `/s/AbC123` |
| 长度 | 随设计变大 | 固定短 |
| 后端 | 不需要 | Worker + KV/DB |
| 部署 | 静态托管 | 静态 + 服务端 |
| 成本 | 0 | 免费额度/几美元 |
| 隐私 | 数据不离开浏览器 | 数据存在服务器 |
| 失效/撤销 | 不能 | 可以 |
| 更新同一个链接 | 不能 | 可以 |
| 访问统计/OG 预览 | 不能 | 可以 |
| 二维码 | 长链接二维码很密 | 适合二维码 |
| 链接寿命 | 站点/格式在就有效 | 依赖服务 |
| 失败模式 | 聊天软件截断 | 服务宕机/额度 |
| 实现量 | 0.5 天 | +1–2 天 |

体积估算：

- 300 个瓦片：JSON 约 30KB → 压缩 3–5KB → base64 4–7KB，hash 可用；
- 1000 个瓦片：JSON 约 100KB → 压缩 10–15KB → base64 14–20KB，开始危险；
- 5000 个瓦片：直接上短链。

推荐：

- **v1 先做 hash**，零后端、最快上线；
- 代码里抽一个 `ShareService` 接口，后续加 Cloudflare Worker + KV 短链；
- 保留 hash 作为短链服务不可用时的兜底；
- 如果你的主要分享渠道是微信/二维码，建议一开始就上短链，多 1–2 天。

### 4.2 PDF（成品展示）

默认：

- A4 横向（画布更宽时自动切横向）；
- 20mm 页边距；
- 标题（赛道名）、副标题（日期/作者）、比例尺、图例、页脚；
- 画布等比适配页面，留白居中；
- 可选：包含 BOM 页、包含网格、包含坐标标注。

技术（已确认）：

- **v1：从场景 SVG 渲染到 300 DPI Canvas，再包进 PDF**；
  - 中文、字体、视觉效果完全可控；
  - 不是矢量，放大看是位图；
  - 300 DPI A4 横向约 3508×2480，文件约 1–4MB；
- v2：矢量 PDF（线条/圆弧直接写入 PDF，中文字体子集嵌入）；
- 不使用 `html2canvas`。

文件命名：`track-<name>-<yyyyMMdd-HHmm>.pdf`。

### 4.3 PNG 截图（快速展示）

两种范围：

- 当前视图；
- 整个画布（推荐默认）。

选项：

- 背景：白色 / 透明 / 深色；
- 倍率：1x / 2x / 4x；
- 是否包含网格、标尺、标题；
- 下载 PNG；
- 复制到剪贴板（`ClipboardItem`）。

实现：

- 从模型构建 SVG 场景（不含 UI 浮层）→ `Blob` → `Image` → Canvas → `toBlob`；
- 裁切到画布边界 + 24px 内边距；
- 文件命名：`track-<name>-<yyyyMMdd-HHmm>.png`。

### 4.4 DXF（CAD/Fusion/3ds Max 草图）

目标：2D 平面草图，单位毫米，可在 CAD 中继续编辑。

坐标：

- 1 米 = 1000 单位；
- DXF `$INSUNITS = 4`（毫米）；
- 画布左下角为原点，Y 轴向上；屏幕坐标导出时翻转 Y。

图层：

| 图层 | 内容 | 默认 |
|---|---|---|
| `TRACK_CENTER` | 赛道中心线 | 开 |
| `TRACK_EDGE` | 赛道边线 | 开 |
| `TILE_OUTLINE` | 瓦片外框 | 关 |
| `START_FINISH` | 起终点线 | 开 |
| `GRID` | 网格 | 关 |
| `TEXT` | 标注 | 开 |

实体：

- `LINE`、`ARC`、`CIRCLE`、`POLYLINE`（R12）或 `LWPOLYLINE`（R2000）；
- 每种瓦片定义为 DXF `BLOCK`，实例用 `INSERT`，带旋转/镜像；
- 这样 CAD 里文件小、可编辑、可替换；
- 如果某些导入器对块支持不好，提供「炸开为线段」选项。

版本：

- **R12 ASCII（AC1009）**：兼容 3ds Max 最好，用 `POLYLINE`；
- **R2000 ASCII（AC1015）**：Fusion 360 / AutoCAD 更现代，用 `LWPOLYLINE`；
- 导出对话框二选一，默认 R12。

几何 IR（SVG 和 DXF 共用，避免解析 SVG）：

```ts
type Pt = { x: number; y: number };

type Primitive =
  | { kind: 'line'; a: Pt; b: Pt }
  | { kind: 'arc'; center: Pt; r: number; startDeg: number; endDeg: number }
  | { kind: 'circle'; center: Pt; r: number }
  | { kind: 'polyline'; pts: Pt[]; closed?: boolean };

interface GeometryLayer {
  layer: 'TRACK_CENTER' | 'TRACK_EDGE' | 'TILE_OUTLINE' | 'START_FINISH' | 'TEXT';
  primitives: Primitive[];
}
```

- 瓦片本地坐标以米为单位，原点在瓦片左上角；
- 导出时统一变换到全局米，再 ×1000 转毫米；
- ARC 角度按 DXF 逆时针方向处理，注意翻转/旋转后的方向；
- 起终点线单独图层，方便 CAD 里识别。

验证：

- 用 Python `ezdxf` 读回导出文件，检查：
  - 单位、图层、实体数量；
  - `$EXTMIN/$EXTMAX` 是否覆盖画布；
  - 块/INSERT 的旋转和位置；
  - 是否有零长度线段、NaN 坐标；
- 至少用 LibreCAD/QCAD 或 Fusion 手动导入一次，确认视觉正确；
- 3ds Max 用 R12 版本测试导入。

- 代码抽 `ShareService` 接口，先 A，后补 B，B 不可用时回退 A。
