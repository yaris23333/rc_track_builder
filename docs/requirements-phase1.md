## 1. 背景与定位

### 1.1 要解决的问题

RC 赛道（越野、平跑、漂移）的平面方案目前有三种做法，各有明显缺陷：

| 做法 | 问题 |
|---|---|
| 纸笔/白板画 | 比例失真，无法复用，无法交接 |
| 直接用 CAD 画 | 学习成本高，拼装靠手，改一处要重画 |
| 参考站的图片铺格子工具 | 没有真实尺寸、没有端口、没有闭合校验、输出不可施工 |

目标用户真正需要的是：**像拼乐高一样拼赛道，拼完能直接拿去搭，还能交给 CAD 深化。**

### 1.2 产品定位

> 零安装的**赛道草图 + 搭建示意图**工具，向上衔接 CAD 做深化设计，向下提供 AI 可直接调用的生成/校验接口。

四层能力：

| 层 | 内容 | 对应需求 |
|---|---|---|
| 草图层 | 网格沙盘 + 瓦片拼装 + 可视化测量 | FR-01 ~ FR-05 |
| 搭建层 | 带编号、清单、基准、比例的 PNG/PDF | FR-06 |
| 交接层 | DXF（AutoCAD / Fusion 两个预设） | FR-08 |
| 智能层 | headless core + MCP + Skill + 开源瓦片包 | FR-10 ~ FR-13 |

FR-07（分享）与 FR-09（导入导出/自动保存）是跨层支撑能力，不单独占一层。

### 1.3 设计原则

1. **低门槛优先**：默认路径不超过三步（选瓦片 → 点画布 → 导出），不为专业功能牺牲新手体验。
2. **物理尺寸优先**：米是唯一事实来源，格子只是吸附与显示网格。
3. **单向交接**：编辑器负责"想清楚"，CAD 负责"画准确"；不承诺双向同步。
4. **数据即契约**：`TrackDoc` / `TileDef` / Issue 码表是对外 API，先定契约再写实现。
5. **AI 可调用**：所有能力先做成无 DOM 的纯函数，再包 UI 和 MCP。

### 1.4 与 CAD 的边界

AutoCAD 能覆盖"网格 + 块库 + 吸附 + 出图"，但覆盖不了"端口语义、连通、闭合、占位碰撞"：

- 动态块的约束是**块内**的，不是块间的；一个块只能有一张块表；
- Civil 3D 装配/corridor 是线性工程模型，不适合二维自由拼装；
- Map 3D 拓扑只能检查线稿是否围合，不理解赛道语义；
- Vehicle Tracking 是唯一专业对口的能力（车宽扫掠），作为下游验证手段。

因此 AutoCAD 在本产品中**只做出口，不做编辑器**。重开插件路线的条件见 §8 D2。

## 2. 目标与成功标准

| # | 目标 | 衡量方式 | 一期验收 |
|---|---|---|---|
| G1 | 不会 CAD 也能快速拼赛道 | 新用户首次完成闭合赛道的时间 | ≤ 3 分钟 |
| G2 | 输出可现场搭建的平面图 | 只看图纸能否完成摆放 | 30×20 m 赛道，A4 打印可读、编号与清单齐全 |
| G3 | DXF 可被专业软件直接使用 | AutoCAD/Fusion 打开后的可操作性 | AutoCAD 按块统计；Fusion 草图闭合可拉伸 |
| G4 | 开源 + AI 高度支持 | 外部 agent 端到端任务 | 生成 → 校验 → 修复 → 导出全流程通过 |

## 3. 范围

### 3.1 一期包含

- 已实现的 v1 基线（网格、瓦片、编辑、PNG/PDF/链接/DXF 初版）；
- 本期新增：端口与闭合校验、搭建图、测量工具、DXF 双预设、headless core、MCP、Skill、开源工程化；
- 数据契约：`TrackDoc`、`TileDef.ports`、Issue 码表、JSON Schema。

### 3.2 一期不包含

- 浏览器内瓦片几何编辑器（贝塞尔/约束/端口绘制）；
- 3D 地形、物理引擎、车辆动力学仿真；
- 多人实时协作、账号体系、云端项目；
- 双向 CAD 同步；
- 施工级工程图、CNC/加工文件；
- 移动端适配；
- 全自动生成完整赛道（AI 只做辅助生成 + 校验，不替代用户决策）。

### 3.3 版本口径

一期 = **v1 基线（已实现）+ 本期 P0/P1 增量**。文中「状态」列用于区分：

| 状态 | 含义 |
|---|---|
| 已实现 | v1 已上线，本文只做需求追溯 |
| 待开发 | 需求已确认，进入本期排期 |
| 待细化 | 方向确认，细节未定，见附录 B |
| 不做 | 明确排除，见 §3.2 |

## 4. 用户与场景

### 4.1 用户角色

| 角色 | 特征 | 核心诉求 |
|---|---|---|
| 新手玩家 | 没接触过 CAD，手机/电脑都能看 | 快速拼一条能跑的赛道，分享给朋友 |
| 俱乐部/场地搭建者 | 有固定场地，要组织比赛 | 可打印的搭建图、物料清单、尺寸 |
| CAD 深化设计师 | 用 AutoCAD/Fusion | 拿到带块和闭合边界的 DXF，继续深化 |
| AI 使用者/开发者 | 用 Claude/Cursor 等 | 用自然语言生成、校验、导出赛道 |

### 4.2 关键场景

**US-01 快速出图**
作为新手玩家，我想在浏览器里拖几块瓦片拼成闭环，导出 PNG 发群里。
验收：从打开页面到导出 PNG ≤ 3 分钟，无需注册。

**US-02 现场搭建**
作为场地搭建者，我想打印一张带编号和清单的图，按图摆放。
验收：图纸含基准角、尺寸链、BOM，现场无需再计算。

**US-03 CAD 深化**
作为设计师，我想把方案导进 AutoCAD 继续标注、算量，或导进 Fusion 做 3D。
验收：DXF 在 AutoCAD 中可按块统计；在 Fusion 中草图闭合可拉伸。

**US-04 AI 生成**
作为 AI 使用者，我想说"给我一条 30×20 米、带两个跳台的新手赛道"，工具能生成并告诉我哪里没接上。
验收：agent 通过 MCP 完成生成、校验、修复、导出，错误可定位。

## 5. 功能需求

> 每条需求包含：优先级、状态、描述、规则、验收。验收标准即测试用例来源。

### FR-01 网格与画布

- **优先级**：P0　**状态**：已实现
- **描述**：提供以米为事实来源的正方形网格画布，支持尺寸设置、缩放、平移、适配。
- **规则**：
  - 格子边长可选 `0.3 / 0.5 / 1 m`；
  - 画布宽高必须是格子边长的整数倍，否则禁用应用并提示最近合法值；
  - 切换格子边长时，瓦片米坐标不变，赛道不缩放、不移动；
  - 缩小画布前提示将被移除的瓦片数，操作可撤销；
  - 网格线用单条 SVG path 渲染，不得一格一个 DOM。
- **验收**：
  - 30×20 m、1 m 网格下为 30×20 格；切到 0.3 m 后为 100×67 格，瓦片坐标不变；
  - 输入 30.1 m（1 m 网格）时应用按钮禁用，并提示 `30 m / 31 m`。

### FR-02 瓦片库与放置

- **优先级**：P0　**状态**：已实现（端口吸附为新增）
- **描述**：提供 8 种 3×3 m 内置瓦片，支持放置、移动、旋转、翻转、删除、多选与撤销。
- **规则**：
  - 瓦片真实尺寸 3×3 m，旋转仅支持 90° 倍数，翻转只做镜像；
  - 点击选中瓦片，再点击画布放置；拖动移动；`R` 旋转；`F` 翻转；`Delete` 删除；
  - `Shift` + 点击多选，支持批量旋转/翻转/删除/复制；
  - 撤销/重做至少 80 步；
  - 放置预览时，附近可连接端口显示吸附提示（依赖 FR-03）。
- **验收**：
  - 8 种瓦片均可放置、旋转、翻转、删除；
  - 多选批量操作后撤销可完整恢复；
  - 端口吸附后两块瓦片的连接端口坐标误差 < 1e-6 m。

### FR-03 端口与连接

- **优先级**：P0　**状态**：待开发
- **描述**：为每块瓦片定义端口，使瓦片之间可以判定"是否接上"，并为闭合校验、AI 生成、DXF 中心线提供基础。
- **规则**：
  - 端口定义：所在边（`n/e/s/w`）、沿边偏移（0..1）、语义方向（`in/out/both`）、车道宽；
  - 连接判定：世界坐标距离 < 1e-6 m，且法线点积 < -0.999；
  - 车道宽不一致只告警，不阻断；
  - 端口世界坐标必须使用固定变换顺序：flip → rotate（绕瓦片中心）→ translate；
  - 端口可开关显示，默认在编辑时显示。
- **验收**：
  - 直线 + 90° 弯可正确相接，旋转/翻转后端口仍对齐；
  - 未连接端口在画布上可识别（颜色/形状区分）；
  - 契约测试覆盖 4 个旋转 × 4 种翻转组合。

### FR-04 闭合校验与问题提示

- **优先级**：P0　**状态**：待开发
- **描述**：实时判断赛道是否构成唯一闭合回路，并把问题定位到具体瓦片与端口。
- **规则**：
  - 图节点 = 瓦片，边 = 端口连接；
  - 每块瓦片度数必须为 2；图必须连通；起终点瓦片必须在回路上；
  - 一期只支持单回路，8 字/立交（度数 4）判为未闭合，留到后续；
  - 问题以稳定错误码返回（见 §6.4），带 `uid`、端口、坐标、修复提示；
  - 顶部状态徽标显示闭合状态与断点数；点击问题可定位；
  - 校验可关闭（性能兜底），默认开启。
- **验收**：
  - `fixtures/` 中 6 个文档（闭合、缺一块、重叠、越界、8 字、无端口）返回稳定 Issue 列表；
  - 同一文档多次校验结果字节级一致；
  - 500 块瓦片校验 < 100 ms。

### FR-05 测量与坐标

- **优先级**：P0　**状态**：待开发
- **描述**：让用户不借助 CAD 就能在画布上量距离、读坐标。
- **规则**：
  - 工具栏标尺按钮或快捷键 `M` 进入测量；
  - 点击两点，实时显示 `Δx`、`Δy`、直线距离（米，1 位小数）；
  - 吸附网格点、端口、瓦片中心；
  - `Esc` / 右键 / 再次点击退出；结果保留到手动清除；
  - 状态栏常驻显示光标坐标 `x, y m` 与格子 `col, row`。
- **验收**：
  - 测量 3 m 直线显示 3.0 m；
  - 缩放/平移后测量结果不漂移。

### FR-06 搭建图导出（PDF / PNG）

- **优先级**：P0　**状态**：待开发（PDF 增强）
- **描述**：把方案导出为可现场使用的搭建图，而非仅展示图。
- **规则**：
  - 编号：每块瓦片有 ID（`A1`、`A2`…，按 `row` 优先、`col` 次之），A4 打印可读；
  - 清单：瓦片类型 × 数量、总面积、瓦片总数；中心线总长可选（P1）；
  - 定位：左下角基准角 `DATUM`、外包尺寸、沿下边/左边的尺寸链（3 m 刻度）；
  - 比例：比例尺 + "按 100% 打印" + 100 mm 校验条；
  - 提示：从基准角先摆外圈、每 5 块复核对角线、朝向箭头指示车头；
  - 页脚：生成时间、应用版本、免责声明"非工程图纸，尺寸以现场复核为准"；
  - PNG：2× 位图，默认无网格，可选含网格。
- **验收**：
  - 30×20 m、约 60 块瓦片的赛道，A4 横向打印后编号与 BOM 可读；
  - BOM 数量与画布统计一致；
  - 尺寸链总和等于画布实际尺寸；
  - 100 mm 校验条实际打印为 100 mm（±1 mm）。

### FR-07 分享链接

- **优先级**：P1　**状态**：已实现
- **描述**：无需后端，把方案压缩进 URL，打开即看。
- **规则**：
  - 路由 `/#/s/<deflate + base64url>`，数据不经过服务器；
  - 打开为只读预览，可"复制到本地"继续编辑；
  - 链接 < 6 KB 直接分享；6–20 KB 提示可能被截断；> 20 KB 建议导出 JSON；
  - 解码上限 2 MB，不执行用户文本。
- **验收**：
  - 22 块瓦片的链接约 1.3 KB 且可正常打开；
  - 超限文档给出明确提示，不生成坏链接。

### FR-08 DXF 导出

- **优先级**：P0　**状态**：待开发（双预设）
- **描述**：把方案导出为 CAD/Fusion 可用的交接文件。
- **规则**：
  - 单位毫米，Y 轴向上，原点为画布左下角，`$INSUNITS = 4`；
  - `cad` 预设：每个用到的 `TileDef` 一个块（`RC_<DEFID>`），每个放置实例一个 `INSERT`；块参照带 XDATA（`RC_DEFID`/`RC_UID`/`RC_ROT`，需注册 `RC_TRACK` APPID）；块内 `OUTLINE` 为闭合 `LWPOLYLINE`；
  - `fusion` 预设：无块、全部炸开，外轮廓与赛道边线为闭合 `LWPOLYLINE`；可选输出闭合中心线（P1）；
  - 图层：`BOARD`、`TILE_OUTLINE`、`TRACK_EDGE`、`TRACK_CENTER`、`FEATURE`、`START_FINISH`、`TEXT`；
  - `cad` 预设可在 `$COMMENTS` 写入 `RCTRACK:<base64url(deflate(doc))>` 作为未来回传锚点；
  - R12 不支持 XDATA 时用块名 + `TEXT` 标签替代；中文文本回退英文。
- **验收**：
  - AutoCAD 打开后 `QSELECT` 可按块名统计数量；
  - Fusion 导入后草图闭合、可拉伸，3 m 瓦片 = 3000 mm；
  - 两个预设均通过 `ezdxf` 解析且无结构错误。

### FR-09 项目导入导出与自动保存

- **优先级**：P0　**状态**：已实现（契约增强）
- **描述**：项目的保存、恢复、迁移。
- **规则**：
  - JSON 导入/导出，含 `schemaVersion` 与 `tileSetVersion`；
  - 自动保存到 localStorage/IndexedDB，刷新恢复；
  - 导入时按 §6 契约校验，失败给出可读原因，不静默丢弃；
  - v1.0 文档可直接读取，缺失端口按内置表补全，`tileSetVersion` 升至 `1.1.0`。
- **验收**：
  - 导出→导入往返后文档等价；
  - 篡改 `defId` 的文档被拒绝并提示具体字段。

### FR-10 瓦片包（自定义瓦片）

- **优先级**：P2　**状态**：待细化
- **描述**：允许通过数据包扩展瓦片，不开放浏览器内几何编辑器。
- **规则（初稿）**：
  - 格式为 `TileDef` JSON（含 `ports`），支持单文件或包清单；
  - 导入流程：schema 校验 → 预览 → 入库；
  - 纯数据，不执行脚本、不引用外部 URL；
  - 尺寸非 3 m 时告警；端口必须落在边上；
  - 支持"自然语言 → `TileDef` JSON → 校验 → 预览"的 AI 生成路径。
- **验收（待细化）**：
  - 外部瓦片包导入后可放置、可连接、参与闭合校验；
  - 非法包被拒绝且不影响现有数据。

### FR-11 AI 接口（MCP Server）

- **优先级**：P1　**状态**：待开发
- **描述**：以 MCP 暴露编辑器的核心能力，让外部 agent 能生成、校验、修复、导出赛道。
- **规则**：
  - stdio 传输，`npx @rctrack/mcp` 启动，Node ≥ 20，无网络依赖；
  - 工具入参用格子坐标（整数），内部换算米；
  - 工具集与返回契约见 §6.6；
  - `validate_track` 必须返回结构化 Issue，供 agent 自修复；
  - 文件写入限制在工作目录 `out/`，拒绝路径穿越；
  - `png`/`pdf` 需可选渲染依赖；未安装时返回 `RENDER_UNAVAILABLE` 并降级 `svg`/`json`，不静默失败。
- **验收**：
  - 在 Claude Desktop / Cursor 中通过 3 条自然语言指令生成闭合赛道并导出 DXF；
  - 人为删掉一块后，agent 能按 `PORT_GAP` 的 `at`/`hint` 自行修复。

### FR-12 AI 技能（Skill）

- **优先级**：P1　**状态**：待开发
- **描述**：把"怎么用工具做好赛道"沉淀为可复用的技能说明，MCP 给能力，Skill 给流程与品味。
- **规则**：
  - 结构：`SKILL.md` + `references/tiles.md` + `references/issues.md` + 3 个示例；
  - 流程：明确场地 → 选型 → 铺外圈 → 补内部 → 每 5–6 块校验 → 闭合 → 导出 → 汇报 BOM；
  - 不变量：每块度数 2、端口成对、起终点在回路上、不越界不重叠；
  - 示例：小椭圆、跳台段、技术弯组合（8 字/立交不在本期）。
- **验收**：
  - Skill + MCP 组合下三个示例均可复现；
  - 失败时输出可读的断点位置与修复建议。

### FR-13 开源与社区

- **优先级**：P1　**状态**：待开发
- **描述**：以开源方式发布，支持外部贡献瓦片与工具。
- **规则**：
  - 仓库含 LICENSE、CONTRIBUTING、CI、`tiles/`、`examples/`；
  - 瓦片以纯数据贡献，改 JSON 即可新增，无需改代码；
  - CI：typecheck → test → build → 校验 examples → DXF 快照；
  - npm 发布 `@rctrack/core`、`@rctrack/mcp`；
  - README 提供"使用者 / 瓦片作者 / AI 开发者"三条入口。
- **验收**：
  - 外部开发者只改 `tiles/*.json` 即可新增瓦片并通过 CI；
  - 新贡献者按 CONTRIBUTING 可在 30 分钟内跑通本地环境。

## 6. 数据与接口契约

### 6.1 TrackDoc

```ts
interface TrackDoc {
  schemaVersion: 1;
  name: string;
  board: { cellSize: 0.3 | 0.5 | 1; widthM: number; heightM: number };
  tiles: PlacedTile[];
  meta: { author?: string; notes?: string; createdAt: string; updatedAt: string };
  tileSetVersion: string;   // 1.0.0 → 1.1.0（新增 ports）
}
```

字段只增不改；变更必须升 `schemaVersion` 并保留旧版读取路径。

### 6.2 TileDef 与 Port

```ts
type Side = 'n' | 'e' | 's' | 'w';

interface Port {
  id: string;          // 瓦片内唯一，如 'in' / 'out' / 'w' / 'e'
  side: Side;          // 所在边
  offset: number;      // 沿边位置 0..1，默认 0.5（边中点）
  dir: 'in' | 'out' | 'both';
  laneWidth: number;   // 车道宽（米），默认 1.5
}

interface TileDef {
  // ...既有字段（id/name/category/sizeM/primitives）
  ports?: Port[];      // 缺失时视为"不可连接"
}
```

端口点规则：`n` 上边（y=0）沿 +x 偏移；`e` 右边（x=w）沿 +y；`s` 下边（y=h）沿 -x；`w` 左边（x=0）沿 -y。法线分别为 `(0,-1)`、`(1,0)`、`(0,1)`、`(-1,0)`。

### 6.3 坐标变换顺序（固定）

```text
局部坐标
  → flipX: x' = w - x（flipY 同理 y' = h - y）
  → rotate(rotation, 中心 = (w/2, h/2))
  → translate(xM, yM)
```

端口世界坐标与法线必须同序变换，否则 AI 生成的放置参数会与几何错位。

### 6.4 Issue 码表（稳定契约）

| code | 级别 | 含义 | 修复提示 |
|---|---|---|---|
| `UNKNOWN_DEF` | error | 引用了不存在的瓦片定义 | 检查 `defId` |
| `DUPLICATE_UID` | error | uid 重复 | 重新生成 uid |
| `OUT_OF_BOARD` | error | 瓦片超出画布 | 移动或扩大画布 |
| `TILE_OVERLAP` | error | 占位重叠 | 移动其中一块 |
| `PORT_GAP` | error | 端口未连接 | 在 `at` 处补一块瓦片 |
| `PORT_MISMATCH` | error | 端口重合但法线/宽度不符 | 旋转或更换瓦片 |
| `NO_PORTS` | warning | 瓦片无端口定义 | 补端口或忽略 |
| `NOT_CLOSED` | error | 不构成单一闭合回路 | 检查断点与度数 |
| `NO_START` | warning | 缺少起终点瓦片 | 加入起终点 |
| `TANGENT_KINK` | warning | 中心线切向突变 > 45° | 检查弯道方向（P1） |

### 6.5 DXF 预设

| 预设 | 目标软件 | 形态 |
|---|---|---|
| `cad` | AutoCAD | BLOCK + INSERT + XDATA，可继续拼装、统计、标注 |
| `fusion` | Fusion 360 | 炸开的闭合多段线，直接当草图拉伸/偏移 |

原因：Fusion 导入 DXF 会把块拆成草图几何，块结构对它无意义；一个文件无法两边最优。

### 6.6 MCP 工具契约

| 工具 | 入参 | 返回 |
|---|---|---|
| `list_tiles` | — | `[{ id, name, sizeM, ports, description }]` |
| `create_track` | `name?, widthM, heightM, cellSize` | `{ doc }` |
| `place_tile` | `defId, col, row, rotation?, flipX?, flipY?` | `{ doc, uid, issues }` |
| `move_tile` | `uid, col, row` | `{ doc, issues }` |
| `remove_tile` | `uid` | `{ doc }` |
| `validate_track` | — | `{ closed, issues, stats }` |
| `describe_track` | — | `{ tiles, closed, bbox, bom, lengthM }` |
| `export_track` | `kind: png\|pdf\|dxf\|json\|svg`, `preset?` | `{ path }` 或 `{ data }` |

资源：`rctrack://schema/track-doc`、`rctrack://tiles`、`rctrack://examples/{name}`。

### 6.7 JSON Schema 与版本

- `schema/track-doc.schema.json`、`schema/tile-def.schema.json` 为唯一契约；
- `additionalProperties: false`，坐标 3 位小数，数组顺序稳定（`y`、`x`、`uid`）；
- 契约测试进 CI，MCP 入参出参复用同一 schema。
